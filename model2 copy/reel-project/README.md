# Automated Slideshow Reel — Architecture Guide

A fully automated audio-synced Instagram/Reel slideshow generator.
Drop in images + an audio file, get a polished vertical video with beat-synced transitions.

---

## Folder Structure

```
Slideshow-with-AudioSync/
|
+-- Git-2/
|   +-- beat-detection/
|       +-- detect_beats.py        <- Python AI beat detector (runs first)
|
+-- model2 copy/
    +-- reel-project/              <- The main Remotion video project
        +-- public/                <- DROP YOUR IMAGES + AUDIO HERE
        |   +-- Sample_1.mp3
        |   +-- photo1.jpg
        |   +-- ...
        |
        +-- src/
        |   +-- main.tsx           <- STAR: Composition config (duration, FPS, min/max gap)
        |   +-- Reel.tsx           <- STAR: The video renderer (scenes, transitions, audio)
        |   +-- layout.ts          <- How images are grouped into scene types
        |   +-- data.ts            <- AUTO-GENERATED: image list + audio path + title
        |   +-- beats.ts           <- AUTO-GENERATED: beat timestamps from the audio
        |   +-- Root.tsx           <- (unused legacy file, ignore)
        |
        +-- scripts/
        |   +-- trim-to-audio.js   <- Post-render ffmpeg trimmer (optional)
        |
        +-- scan-images.mjs        <- Pre-render orchestrator (runs beat detection + scans images)
        +-- package.json           <- npm scripts
```

## How It All Works — Step by Step

When you run `npm run studio` or `npm run render-reel`, this is the exact chain of events:

```
npm run studio
    |
    +-- 1. node scan-images.mjs
    |       +-- Scans public/ for images -> shuffles them randomly
    |       +-- Calls Python: detect_beats.py (from Git-2 folder)
    |       |       +-- Analyses the audio with librosa
    |       |       +-- Detects drum hits, spectral novelty, beat grid, structure
    |       |       +-- Outputs raw beat timestamps -> beats_temp.txt
    |       +-- Reads beats_temp.txt, clamps gaps, pads to 100 entries
    |       +-- Applies -40 frame sync shift (so wipe starts before the beat)
    |       +-- Writes -> src/beats.ts  (cumulative frame numbers)
    |       +-- Writes -> src/data.ts   (image list + audio path + title)
    |
    +-- 2. remotion preview src/main.tsx
            +-- main.tsx reads beats.ts + data.ts
            +-- Computes clamped scene durations (min/max gap enforced here)
            +-- Calculates exact totalDuration for the composition
            +-- Passes scenes + beatFrames -> Reel.tsx for rendering
```

## What Each File Does

### scan-images.mjs — The Orchestrator

Runs before every preview/render. It:
- Scans `public/` for images (`.jpg`, `.jpeg`, `.png`, `.webp`)
- Calls `detect_beats.py` from the `Git-2` folder via a shell command
- Enforces a minimum gap between beats (filters out beats that are too close)
- Splits large gaps (>3s) into 2.5s chunks so no scene is too long
- **Pads the list to at least 100 beat entries** — ensuring the video always has enough timeline slots
- Applies a **-40 frame shift** to all beat positions so transitions visually land *on* the beat (because the wipe animation starts 40 frames before the beat hits)
- Overwrites `src/beats.ts` and `src/data.ts`

### Git-2/beat-detection/detect_beats.py — The AI Brain

A 4-layer Python beat analyser using the `librosa` audio library:

| Layer | What it detects | Priority weight |
|-------|----------------|----------------|
| Phrase grid | Regular rhythmic beat grid from BPM | 1.0 |
| Drum onsets | Hard percussion hits (kicks/snares) | **3.0** |
| Spectral novelty | Timbral changes (drops, builds) | 1.0 |
| Structural segments | Verse/chorus boundaries | 2.0 |

All candidates are scored and the best ones are selected using a voting system, with a minimum gap enforced between them.

### src/beats.ts — AUTO-GENERATED

Contains an array of **cumulative frame numbers** — each number is the frame at which a beat ends.

```ts
export const beatFrames = [10, 61, 99, 136, ...];
// beat 0 ends at frame 10
// beat 1 ends at frame 61 (gap = 51 frames = ~2.1s)
// etc.
```

> WARNING: Do not edit this file manually. It is overwritten on every `npm run studio`.

### src/data.ts — AUTO-GENERATED

Contains the shuffled image list, audio source, and title:

```ts
export const EVENT_NAME = "My Memories";   // <- title shown on first scene
export const AUDIO_SRC = "Sample_1.mp3";
export const IMAGES: ImageAsset[] = [ ... ];
```

> WARNING: Do not edit this file manually. It is overwritten on every `npm run studio`.

### src/layout.ts — Image-to-Scene Grouper

Takes the flat image list and groups them into 4 scene types:

| Scene type | When it's used | Visual appearance |
|-----------|----------------|-------------------|
| `intro` | Always first 2 images | Two photos split-screen + title overlay |
| `fit_portrait` | Vertical photo (height > width) | Full-screen cover |
| `blurred_bg` | Landscape photo on its own | Photo centred with blurred copy as background |
| `collage` | Two landscape photos paired up | Two photos stacked with blurred bg behind |

### src/main.tsx — Composition Config

Defines the Remotion composition (dimensions, FPS, duration). It:
- Reads the auto-generated `beats.ts` and `data.ts`
- Builds scenes via `processImagesToFrames()`
- Enforces min/max visible time per scene via clamping
- Computes the exact `totalDuration` so the composition has no dead frames
- Passes pre-computed `scenes` and `beatFrames` as props to `Reel.tsx`

### src/Reel.tsx — The Video Renderer

The actual Remotion composition component. It:
- Receives `scenes` and `beatFrames` as props (no local re-computation)
- Maps each scene to a `Series.Sequence` with overlap for the wipe transition
- Re-applies the min/max clamp when computing each scene's duration
- Plays the audio with `endAt={durationInFrames}` so it stops exactly when the last image ends
- Renders the 4 scene layout types with Ken-Burns zoom + wipe-in animations

## How to Change Things

### Change the Title

The title appears **only on the first scene** (the intro card with two photos split-screen).

Open `scan-images.mjs` and find this line near the bottom (~line 146):

```js
export const EVENT_NAME = "My Memories";   // <- Change this string
```

**Why here and not in `data.ts`?**
Because `data.ts` is auto-generated and overwritten on every run. The source of truth lives in `scan-images.mjs`.

---

### Change the Min/Max Slide Duration

There are **two files** that must be kept in sync — if you change one, change the other too.

**1. src/main.tsx** (near the top):
```ts
const MIN_SLIDE_FRAMES = 2 * FPS;   // minimum seconds x 24
const MAX_SLIDE_FRAMES = 3 * FPS;   // maximum seconds x 24
```

**2. src/Reel.tsx** (near the top):
```ts
const MIN_SLIDE_FRAMES = 2 * FPS;   // must match main.tsx
const MAX_SLIDE_FRAMES = 3 * FPS;   // must match main.tsx
```

Example — change to 2.5s min, 4s max:
```ts
const MIN_SLIDE_FRAMES = 2.5 * FPS;
const MAX_SLIDE_FRAMES = 4 * FPS;
```

> WARNING: Both files must have the same values or the composition length will drift from what's actually rendered.

---

### Change the Beat Detector's Minimum Gap

The beat detector's own minimum gap filter lives in `scan-images.mjs` (~line 70):

```js
execSync(`python "${pythonScript}" "${fullAudioPath}" --out ... --min-gap 2.0`, ...);
//                                                                        ^^^
//                                             Minimum seconds between detected beats
```

Change `--min-gap 2.0` to your preference (e.g. `--min-gap 1.5` for faster songs).

> Note: This is the beat detector's pre-filter. The frame-level min/max clamp in `main.tsx` and `Reel.tsx` is a second safety net that runs after.

---

### Change the Transition (Wipe) Speed

The wipe animation runs for `TRANSITION_OVERLAP` frames at the start of each scene.

In **src/Reel.tsx** (near the top):
```ts
const TRANSITION_OVERLAP = 24;   // 24 frames = 1 second at 24fps
```

Also update in **src/main.tsx**:
```ts
const TRANSITION_OVERLAP = 24;   // must match Reel.tsx
```

| Value | Speed |
|-------|-------|
| `12` | Very fast (0.5s) |
| `24` | Normal (1s) — default |
| `36` | Slow (1.5s) |
| `48` | Very slow (2s) |

> WARNING: `TRANSITION_OVERLAP` must be less than `MIN_SLIDE_FRAMES` or scenes will overlap incorrectly.

---

### Change the Song or Images

Just drop new files into the `public/` folder:
- Replace or add `.mp3` / `.wav` audio (the first audio file found is used)
- Replace or add `.jpg` / `.jpeg` / `.png` / `.webp` images
- Run `npm run studio` — everything regenerates automatically

## How Git-2 Connects to This Project

The `Git-2/beat-detection/` folder is a standalone Python module. It is called by `scan-images.mjs` via a direct shell command:

```js
// scan-images.mjs ~line 65
const pythonScript = path.resolve('../../Git-2/beat-detection/detect_beats.py');
execSync(`python "${pythonScript}" "${fullAudioPath}" ...`);
```

The relative path `../../Git-2/...` assumes this exact folder layout:

```
Slideshow-with-AudioSync/
    +-- Git-2/beat-detection/detect_beats.py   <- Python script
    +-- model2 copy/reel-project/              <- npm project (you are here)
```

> WARNING: If you move either folder, update the `path.resolve('../../Git-2/...')` line in `scan-images.mjs`.

**The handshake:**
1. `scan-images.mjs` calls `detect_beats.py` -> raw timestamps written to `beats_temp.txt`
2. `scan-images.mjs` reads `beats_temp.txt` -> converts to frame numbers -> writes `src/beats.ts`
3. `beats_temp.txt` is deleted after use

## Timing Math Reference

```
Raw beat gap (from beats.ts)
    |  clamp to [MIN_SLIDE_FRAMES, MAX_SLIDE_FRAMES]
    v
Visible gap  (2s-3s of a scene before the next one starts)
    |  + TRANSITION_OVERLAP (for non-last scenes)
    v
Scene duration in Series
    |  next scene offset = -TRANSITION_OVERLAP
    v
Net timeline advance per scene = visibleGap

Total video length = sum of all visibleGaps
Audio cuts off at  = totalDuration (via endAt prop on <Audio>)
```
